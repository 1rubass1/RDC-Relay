## Release policy chosen for implementation

1. **One registered product identity** `RDC Relay`, publisher `RUBASS`, display/release version **1.6.0**. Keep user-facing UI and About version consistent with payload and ARP. No `RC1 Pilot`, `PRIVATE_FULL_RC1`, `OWNER_G1_GO` or developer unlock flags in the public installer.
2. **Preserve 1.5.18 and its uninstall/rollback data until committed.** The new Host/GUI payload must be staged and hash-verified separately, not overlaid onto a running 1.5.x/RC1 process. Adopt the existing verified full-Host code and safety constraints; do not ship a 1.5 GUI rebranded as 1.6.
3. **No interruption of an active Remote by Setup.** An installer must not stop, kill, log out, revoke, change tokens, alter live Remote or launch a competing Host. When the predecessor is active or the owned/adopted state cannot be proven, fail closed / instruct the user to exit normally. Safe return after a stopped predecessor is allowed; a deliberate deference must not create two Host owners.
4. **Known previous installation is evidence, not permission.** Recognize original per-user 1.5.18 registrations and checked shortcuts. An existing RC1 pilot shortcut must be validated as a distinct migration case, NEVER treated as a foreign target to overwrite or a clean install. Unknown registries/paths, unverified symlinks, altered manifests or competing machine-wide ARP entries must be refused.
5. **Commit last:** first prepare complete verified release payload and reversal metadata; then publish startup entrypoints and Installed Apps identity. On any *handled* error, restore the exact previous files/links/ARP (or, for immutable staging, leave orphaned staging inert) with no automatic guess about an active Remote. For power loss, require a recovery decision based on durable transaction state; a process-memory snapshot alone does not qualify.
6. **Uninstall / rollback must be explicit and testable.** Preserve user settings, OAuth vault and Remote data unless the user separately requests deletion. The stable 1.5.18 rollback installer remains a verified recovery artifact until the new route is tested on disposable Windows.
7. **No paid code signing / MSIX / Store migration.** Owner accepted possible blue SmartScreen reputation warning; security scanning and manifest/integrity checks remain mandatory. Portable must be separately SHA-verified and must not modify Installed Apps/primary shortcuts just by launching.
8. **Release boundary:** only release-eligible source changes are cherry-picked/reviewed into a clean main/stable candidate; `docs/dev`, coordination files and developer fixtures never ship. Public push/tag/stable feed changes require a fresh owner GO.
