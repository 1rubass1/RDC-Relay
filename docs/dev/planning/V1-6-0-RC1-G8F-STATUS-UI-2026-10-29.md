Date: 2026-10-29. Branch: `feature/v1.6-host-gui-owner-pilot`, existing Draft PR #23.

Owner's managed `RDC Relay 1.6.0 RC1` window is now open, in `Host-owned Job` mode. It showed `Remote: Connecting` in the header and an entirely blank original startup/header pane, while sanitized Host log showed two `Remote connected` markers. The original Desktop Commander 0.2.52 kernel was not modified.

**End-to-end live connection confirmed:** through connected Desktop Commander on STARMER, process ancestry of actual command execution was `powershell(29660) → node(22976) → node(10576) → cmd(41868) → node(6724) → cmd(34872) → RC1 Host powershell(42340)`. A separate RC1 GUI powershell(12868) is a Host child. The main desktop shortcut pointed to installed Full RC1 release `rc1-1d13d895e4b53a334c72dc59`. This verifies live tool traffic via the newly Job-owned Remote rather than old 1.5.18. Host and Remote were not stopped/restarted during this investigation.

**Live log check (sanitized):** inspected current Host-owned `remote-*.log` with a FileShare.ReadWrite reader, without exporting raw lines/account/device/token information. Recognized several `Ready` connection markers following an earlier `Fault` marker; at the checkpoint the most recent recognized markers were `Ready`. The screenshot's `Connecting` is a stale UI display; no successful connection status should be inferred *solely* from synthetic log markers, but the independent live tool-ancestry proof confirms actual connection.

## Root causes

1. `RdcOwnerRuntime.Snapshot()` has independent revisions: `snapshot.revision` is based on Host `sequence` for Host events, while `snapshot.remote.revision` changes via `RdcOwnerRemoteState.ManagedStatus()` when Remote connection state moves Connecting → Ready/Fault/etc. `rc1-owner-gui.ps1` previously repainted `Set-State` only when Host revision changed. Sanitized log processing could update `remote.revision` and tail while Host revision stayed constant: new Remote markers appeared in the lower pane, but upper status remained Connecting.
2. The full original GUI's upper `headerLog` renders `$script:startupBlock`. Owner GUI did not initialize this startup block from any private Host snapshot; `Reset-CompactLogSession` cleared it and only `Add-CompletedEvent` populated the lower activity panel. Hence a completely empty original header pane.

## Product fix

- `Source/rc1-owner-gui.ps1`: track `ownerLastShownRemoteRevision` in addition to `ownerLastShownRevision`, and repaint runtime status on *either* revision advancing. The GUI still accepts snapshots only from authenticated IPC for the exact Host generation and actual Remote mode.
- Populate existing original `startupBlock`/upper `RdcLogBox` from only allowlisted Host snapshot values on a state update: `Remote Connection`, pinned Desktop Commander 0.2.52 identity, canonical connection state, numeric PID, and `Managed Host-owned Job` or `Adopted read-only` ownership, with an indication that raw private Remote details remain in Host. Never forward raw startup logs, email, device identifiers, tokens, or unsafe stdout into GUI.
- No changes to true Remote kernel, job stop, transport, update channel, installed application or working Remote processes.
