2026-10-29, existing `feature/v1.6-host-gui-owner-pilot`, Draft PR #23. **No PR merge, stable publishing or changes to Desktop Commander Remote 0.2.52.**

## Owner report

In a live installed Full RC1, connection state and Job-owned Remote PID were now displayed correctly, but the account/footer said "определяю", the upper startup panel only contained a minimal private summary, and Setup showed a redundant informational modal after successful handoff. The owner also requested safe upgrade from a predecessor shell left open when its own Remote has already stopped.

## Product changes

1. **Account + device identity as carefully scoped product IPC state.** In `Source/RdcOwnerRuntime.cs`, the Host reads *only its own managed Job Remote log* and whitelists original pinned Remote startup labels `- User:`, `- Device Name:`, `- Device ID:`. Strict email, printable device-name and UUID validators reject arbitrary log contents, control characters and unexpected labels. ANSI SGR escapes are removed before matching. Parsed fields are stored in Host RAM, reset on new owned Remote/explicit stop/observed Job exit and increment the Remote revision on changes. The authenticated snapshot exposes a `remoteIdentity` with only the three fields; OBSERVED/FAKE gets blanks. No private stdout log, token, account command, environment variable or device secret travels over IPC.
2. **Use original full GUI controls.** `Source/rc1-owner-gui.ps1` validates the Host-provided structured fields again, calls the existing original `Set-AccountDisplay` footer control, and fills the existing upper `startupBlock` with connection status, pinned version, User, Device Name, Device ID, PID, ownership and connection marker. No raw Remote banner is copied; layout remains the original WinForms UI and lower event stream. Header updates when Remote revision changes independently of Host event sequence.
3. **Quiet installation success.** In `Installer/Rc1CandidateSetup.cs`, remove the unconditional success/info popup after a successful manual upgrade. Preserve initial user confirmation (Yes/No), error dialog with error code, and the **actionable warning** for deferred old-Host handoff.
4. **Running previous RC1 Host, no pinned Remote detected.** `Installer/Rc1ManualUpgrade.cs` continues to stage a manifest-verified immutable release. A recognized previous RC1 running Host's mutex normally blocks shortcut replacement. When a conservative WMI scan of *all cmd/node process command lines* finds no pinned Desktop Commander Remote and the target root is the current actual OS LocalAppData path, installer may safely switch the desktop shortcut and retain previous backup **without stopping or launching either Host**; result `SWITCHED_RC1_DEFERRED_OLD_HOST`. An unreadable/unknown scan or any matching Remote refuses. User must **close the old Host via its normal tray exit** before starting from new shortcut. Source `rc1-tray-host.ps1` also rejects a competing Full RC1 Host from another installed release via process identity scan. This provides the requested install staging/shortcut handoff with old GUI open and Remote stopped, but is **not an automatic live Host process replacement** and does **not** prove untrusted processes are owned. Legacy v1.5.18 → RC1 shortcut route remains supported; a live old GUI/Remote is still not force stopped.
