# G111 — Release installer identity, version, publisher, rollback hardening

**2026-11-11 · Programmer implementation candidate. NOT RELEASE APPROVED.** Developed on `feature/v1.6-host-gui-owner-pilot` / Draft PR #23. Existing STARMER installed Stable 1.5.18, registered `UMAS`, and the intentionally switched RC1 Desktop shortcut are **not modified**.

## Owner intent

User-facing releases must **not inherit Owner Pilot temporary behaviors**. The owner specifically explained that the private RC1 side-by-side shortcut handoff and preserved 1.5.18 registration are deliberate for rapid testing and rollback, not a release installer defect. Future releases must have one version identity, correctly registered Windows Installed Apps metadata, `RUBASS` as publisher, a one-sentence upgrade confirmation, no upgrade message on a true fresh install, and rollback coverage of files, shortcuts and registration. The private Pilot remains independent.

## Implemented: stable/public release route only

- `Installer/RdcReleaseInstallState.cs`: read-only Windows detection of the registered per-user RDC Relay, including historical `UMAS` and new `RUBASS`; verifies exact product name, install root, numeric `DisplayVersion` matching `version.txt`, and required GUI/updater files. Checks machine-wide HKLM (32- and 64-bit) for competing registrations; Desktop and Start Menu primary shortcuts are **secondary contradiction checks, not installation evidence**. Missing registration+files/shortcuts, unknown publisher, inconsistent version, foreign shortcut or machine conflict are **Refuse**, never silently Fresh.
- `Installer/Setup.cs`: public Setup checks this policy **before modifying product files**, prompts only for confirmed upgrade with one line **«Установить RDC Relay {version} как основную оболочку?»**, No by default; first install has no replacement prompt. The target version comes from embedded `version.txt` and must match embedded `update-manifest.json`. `Publisher=RUBASS`; legacy `UMAS` is recognized *only* as an allowed old identity.
- `Installer/RdcReleaseMetadataSnapshot.cs`: snapshots user ARP registration values and six expected Desktop/Start Menu link identities before mutations. On handled installation failures Setup requests payload rollback followed by snapshot restoration. Superseded icons and legacy cosmetics are removed only **after** successful transaction commit. Snapshot rollback of shortcuts is tested on disposable directories, no actual user links or registry are changed by tests.
- `Source/remote-window.ps1`: stable GUI now reads strict numeric version from installed `version.txt`, instead of a literal `1.5.18`, and re-registration uses `RUBASS`. RC1 Owner GUI version remains its independent explicit candidate identity.
- `Source/update.ps1`: stable updater now synchronizes installed-app `DisplayVersion`, `Publisher=RUBASS`, and uninstall commands **inside** its file transaction. On failure it attempts restoration of the previous registration. This path is allowed only for the exact default stable installation root; disposable paths never access live Installed Apps registration. The `RC1_UPDATE_BLOCKED` gate remains at script entry.
- `Installer/Launcher.cs`, `Scripts/build-release.ps1`: Setup and Portable EXE metadata use `RUBASS`; version is from `Source/version.txt`. Public builder requires `main`/`stable` branch, clean tree, complete tests and no `rc1-candidate.json`. It **fails before source-mutating build steps** on the Pilot branch. Only a **temporary privately compiled** `RDC_INSTALLER_TEST` Setup accepts `--install-root`, `--no-register`, `--no-shortcuts` for disposable transaction tests; the public binary rejects these flags.
- Prior incomplete G111 Owner Pilot prompt logic remains isolated in `Installer/Rc1CandidateSetup.cs`, `Installer/Rc1ManualUpgrade.cs`, `Scripts/build-rc1-full.ps1`, `Scripts/rc1-version-contract.ps1`, and `Tests/Test-V16ManualSetupPrompt.ps1`. The Pilot intentionally does not modify the stable ARP registration and retains reversible shortcut handoff.

## Explicit gaps and release gates

**NOT CHECKED / NOT RELEASE APPROVED**: real Windows ARP write/rollback fault injection and power-loss/recovery; install/uninstall/upgrade on a **disposable Windows OS image** with clean, old stable, current and ambiguous states; actual UI/DPI, UAC and accessibility; signing and release artifact inspection; independent Reviewer approval; a true production build on a clean `main`/`stable` branch (blocked here intentionally).
