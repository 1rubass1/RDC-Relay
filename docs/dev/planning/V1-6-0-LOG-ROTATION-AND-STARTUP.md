## Rotation and retention contract (byte sink implemented; runtime integration pending)

Stage 2a: Source/RdcOwnerLogParts.cs implements a standalone bounded rotating raw-byte sink (production defaults 10 MiB per part, 512 MiB per session). It requires a new empty owned directory, rotates before subsequent bytes on local date change or exact size boundary, numbers independently by date, and retains monotonic numbers when wall clock goes backward. It never overwrites an existing part. It trims completed parts in actual creation order, verifies path/length before deletion and does not delete the active writer. The explicit Flush uses durable file flush; failure latches the sink, without pretending more bytes were recorded. Isolated tests use small limits and simulated clock with exact binary comparison: 15 PASS / 0 FAIL. The initial test reader needed explicit FileShare.ReadWrite, matching the production snapshot copy. No real log is read or modified.

This class is **not yet in production build allowlists** and has no Host call sites. The current CMD redirection, parser, log selection and Windows shutdown behavior are unchanged. Next integration must preserve kernel Job ownership and implement continuous byte drain, parser parity, durable current/previous publication and recovery; no claim that rotation is active.

- Define a session by a verified Host-owned Remote process tree, not the GUI lifetime. GUI close/reopen, transient network reconnect without process replacement, or calendar rollover do not start a new session. A new verified process after stop/restart/account switch creates a new session.
- Use per-user persistent local application data outside immutable release directories and transient Host run/ticket roots. Directory layout: Logs/CurrentSession and Logs/PreviousSession, plus minimal durable transaction state as needed. Do not log logout helper streams as normal Remote sessions. No raw bytes in IPC, processed journal, network uploads, or diagnostic reports.
- Each part is named YYYY-MM-DD_part-NNN.log (local calendar date; unambiguous monotonic part numbering per date, no overwrite even if clock changes or DST). Size cap 10*1024*1024 bytes. Preserve merged stdout/stderr bytes and byte order, including invalid UTF-8 and ANSI. Maintain one continuous UTF-8/line parser across rotation; rotating file boundaries must not reset event state or split parser semantics.
- Each session independently retains <=512*1024*1024 bytes; remove oldest completed owned parts first, never delete an open writer or follow reparse paths. User-exported copies outside managed retention are independent. Temporary viewer snapshots need a bounded cleanup policy so they do not quietly defeat the 1 GiB limit. A failed/cancelled launch must not replace a good PreviousSession. No uncontrolled deletion of unknown files.
- Current implementation: RdcOwnerManagedProcess.Start constructs cmd.exe redirection `> "remote-<guid>.log" 2>&1`, and RdcOwnerRuntime reads the one file by offset. Renaming or truncating this open destination is NOT safe rotation. Required next implementation: verified inherited stdout/stderr pipe for the same suspended kernel Job, continuous byte drain, bounded rotating sink and parser feed. Preserve all existing Job ownership, pinned npx, observed/fake isolation and no duplicate Remote guarantees. Avoid an unbounded intermediate spool file.
- On verified normal stop/exit, close/drain source then finalize session by durable directory/metadata transition; do not copy hundreds of MiB during shutdown. After an unsuccessful launch retain the last valid previous session. A successfully closed session becomes PreviousSession and next successful Remote becomes CurrentSession. Explicit Open log dialog selects current/previous and any retained part; default latest, opens editable byte-exact snapshot, not live writer.
- Windows shutdown/logoff: subscribe at the Host lifetime (not GUI) to Win32 WM_QUERYENDSESSION/WM_ENDSESSION or equivalent WinForms/SystemEvents implementation, with confirmed end-session notification, bounded work and no blocking confirmation or new Remote actions. Do not rotate on a cancelled shutdown. Flush frequently during normal operation. Finalize only verified owned session; never kill/adopt external Remote. If shutdown interrupts completion or power fails, startup recovery validates journal/owned directories and retains already committed parts, without destructive guessing. Physical durability of last buffered bytes cannot be guaranteed.
- Tests: synthetic byte stream with 10 MiB boundary, newline/UTF8 split across parts, local midnight and backward clock, retention limits, storage failures, failed start, process stop and account switch, cancelled shutdown, abrupt kill and recovery, duplicate/foreign paths, source parser parity. Then guest visual acceptance and restart test in a persistent disposable VM; ordinary Windows Sandbox closure loses its virtual disk.

### Stage 3 — Windows end-session handling (2026-11-24)

Implemented Host-lifetime hidden top-level NativeWindow. WM_QUERYENDSESSION returns TRUE immediately; WM_ENDSESSION(FALSE) is a no-op; WM_ENDSESSION(TRUE) latches once and suppresses new Remote actions and GUI reopening. The confirmed callback requests termination only of the already verified private Remote Job (not a Remote logout or other command) so its output pipe closes, then waits for root/Job completion and drains/publishes the session through the existing transaction.
