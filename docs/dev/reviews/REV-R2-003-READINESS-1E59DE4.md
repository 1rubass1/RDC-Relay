## R2-003-F1 · P2 · После ошибки чтения суффикс JSON становится ложным статусом канала

**Точное место изменения:** `Source/rc1-remote-observer.ps1:330`, вызов `Reset-Rc1ObservedUtf8Stream $ob` в catch.

В предыдущем успешном poll уже могло быть прочитано начало незавершённой физической строки. Offset продвинут, а её начало сохранено в `Fragment` и Decoder. При временном отказе чтения новый catch очищает этот контекст, но оставляет offset на прежнем месте. Следующий poll начинает разбирать оставшийся текст как начало новой строки. Это нарушает требование распознавать только верхнеуровневые сообщения Remote, а не текст внутри данных инструмента.

**Воспроизведение на скрипте из нового сверенного пакета, Windows PowerShell 5.1:**

1. Начальный статус Fault, подтверждения связи нет. В синтетическом файле записать только `{"message":"` и вызвать настоящий observer poll. Получено `Offset=12`, `Fragment={"message":"`.
2. Открыть этот файл с `FileShare.None`, повторить poll. Catch оставляет Fault, но очищает Fragment при прежнем `Offset=12`.
3. Снять блокировку, дописать `Desktop Commander Remote is connected"}` и перевод строки. Весь файл содержит ровно одну JSON-строку `{"message":"Desktop Commander Remote is connected"}`; отдельного сообщения Remote нет.
4. Новый poll ошибочно публикует **Ready** и одно событие соединения.

**Сравнительный контроль:** без промежуточной ошибки та же порционная запись остаётся Fault и не создаёт событие. Тот же тест на ранее проверенном пакете `60049de` остаётся Fault и с ошибкой чтения. Настоящая отдельная строка соединения корректно восстанавливает Ready в обеих версиях. Таким образом, регрессия связана именно с новым сбросом буфера, а не с ожиданиями теста или отсутствием поддержки положительного маркера.

Подменена только проверка OS-идентичности наблюдаемого процесса, чтобы не обнаруживать реальный Remote. FileStream, sharing violation, Decoder, накопление строки, классификатор и основной poll — настоящие. Использован только свой короткоживущий файл; никаких пользовательских журналов.

**Исправление:** сохранить согласованность файловой позиции и состояния декодирования/строки. Если ошибку открытия можно пережить без изменения потока, не терять уже прочитанное начало строки. Если контекст необходимо отбросить, остаток текущей физической строки нужно пропустить до её границы, а не классифицировать как новый статус. Не возвращать старые исторические подтверждения связи повторным чтением всего журнала. Внутренний Fault и обнуление ready proof из текущего исправления сохранить.

**Приёмка:** добавить последовательность partial JSON → IOException → remainder, разрывы UTF-8, слишком длинную строку и аналогичный настоящий статус с корректной границей строки. Подтвердить, что исходные R2-002-F1/F2 не вернулись.

Доказательства: `Test-ObservedPartialReadFailure.ps1`, `partial-read-failure-results.json`; сравнительный `Test-ObservedPartialReadFailure-Baseline.ps1`, `partial-read-failure-baseline-results.json`. Это собственные локальные reviewer probes, не часть текущего штатного runner.
