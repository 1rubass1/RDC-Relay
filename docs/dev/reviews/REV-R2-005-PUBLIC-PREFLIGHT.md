**Проверка кандидата.** Получены SHA-256 Setup `DF6A85FD551DEC2E5522A844AAF02069F56FE85B37E171C44B5A07A18D5F354C` и Portable `4EBF4F517CB8F2C8AA0B9994C5A284DF658E842FE66411BBA03F62B05718D872`. Содержимое всех 30 записей ZIP сверено со staging. Тест Setup сверил 29 ресурсов и манифест. В публичном снимке 68 файлов. Все 35 файлов под FullHost совпали по Git blob с соответствующими staged исходниками, входами компиляции или манифестом. Все 38 реальных raw-файлов обоих поколений совпали с SHA-256 в манифестах. Эти проверки привязывают выводы к выбранному комплекту. Побайтово воспроизводимая пересборка PE не установлена.

**Независимый запуск** в Windows PowerShell 5.1 дал 92/92 для пакета, 10/10 для иконок, 20/20 для загрузчика и 11/11 для старта/перехода диспетчера. Динамические проверки F1–F3 вызывали методы из публичного Setup на текущем пути только для чтения и на собственных временных файлах. Прерывание моделировалось состоянием диска между операциями. Реального отключения питания не проводилось.

**Миграция и доверие.** Legacy сохраняет flat-канал 1.5.18 и фиксированный переход на Setup 1.6.0. У Full Host отдельный типизированный канал более новых версий. Для файлов Setup ограничены HTTPS-хосты, число переходов (5), размер (32 МиБ legacy, 100 МиБ Full Host) и время загрузки. Перед запуском проверяются состояние Remote, SHA-256 с диска и Internet Zone. Содержимое привязано к манифесту в доверенном репозитории. Измеренный статус подписи Setup — NotSigned. Хеш не удостоверяет издателя независимо от репозитория. Решение по подписанию/поддерживаемым политикам Windows и проверка обычного интернет-запуска с сохранённой меткой зоны остаются за владельцем и Architect.

**Транзакции и эксплуатация.** Журнал содержит состояния ярлыков и регистрации до и после применения. Восстановление сверяет допустимые значения и идентичность пакета, а удаление сверяет список файлов, сохраняет общий Node, данные и legacy. После фиксации удаления ошибка физической очистки оставляет остатки и допускает exit 0. Нужна проверка этой ветки на публичном пакете и понятное сообщение об остатках. Переход v1→v2 диспетчера учтён тестом, охват всех частных RC1 не установлен. Maintenance и legacy mutex используют пространство Local Windows-сессии, хотя один пользователь может иметь общие HKCU и файлы во второй сессии. Это статически выявленный риск конкурентного обслуживания. Проверить сериализацию либо явный отказ во второй сессии до записи данных. Фактическую гонку не воспроизводили.

**Разграничение свидетельств.** В архивном результате чистой Sandbox-установки точного Setup зафиксированы ARP 1.6.0, 29 проверенных файлов, оба ярлыка, включённый автозапуск, один Host и один GUI, Remote выключен. Графа кода выхода Setup пуста. В отдельном архивном результате прямой миграции idle 1.5.18 → публичная 1.6.0 зафиксированы exit 0, 29 файлов, ярлыки и сохранённый legacy payload. Это подтверждает сохранение проверенного legacy-файла, но не полное восстановление прежней рабочей версии из резервной копии. Наблюдения получены программистом и проверены ревьюером по архиву.

Удаление и повторная установка, имитация восстановления удаления, числовой переход на 1.6.1 и отказ при понижении ранее проверялись на qualification-сборках. Их результаты не закрывают обслуживание точного публичного бинарника. Остаются обе цепочки обновления через реальную кнопку и HTTP до подтверждённого Setup, загрузка Windows после перезагрузки, прерывание активации в отдельной системе, два сеанса одного пользователя и полный цикл обслуживания публичного пакета. Начинать с исправления F1/F2. Сохранить legacy-откат и продемонстрировать его пригодность, затем повторить проверку с новыми хешами.
