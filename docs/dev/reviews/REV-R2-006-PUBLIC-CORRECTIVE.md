# REV-R2-006 — повторное ревью публичного кандидата RDC Relay 1.6.0

**Решение Reviewer 2 от 25.11.2026 — NO-GO до исправления двух остаточных сценариев.** Проверены исправление `e8902a1ae30bc9cbfde0e45d9ec26cdd243e35f2` и поручение `eec00a1e36be44be2e189c4d0c10d58eff32c5f8`. Исходные отказы из [REV-R2-005](REV-R2-005-PUBLIC-PREFLIGHT.md) устранены в повторённых сценариях. Два новых замечания относятся к доставке обновлений и обслуживанию установки.

| Приоритет | Наблюдение и влияние | Как принять исправление |
| --- | --- | --- |
| **P2 · R2-006-F1. Обновления могут молча исчезнуть при крупном коммите stable** | Упакованный `Source/update-notice.ps1`, функция `Update-RdcUpdateNoticePolling`, получает полное описание коммита, чтобы взять одно поле SHA. Независимая проверка с User-Agent и Accept приложения получила 15 039 байт для текущего stable и 781 177 байт для настоящего preflight-коммита `a6580eb`. Клиент из пакета принял первый ответ и отклонил второй по лимиту 262 144 байта. При таком ответе на stable обработчик завершает проверку до запроса манифеста. Отказ воспроизведён на фиксированном коммите, текущий stable работает. | Оставить ограничение ответа и проверять указатель ветки через компактный Git ref. Тем же клиентом ответ для `git/ref/heads/release/v1.6.0-preflight` занял 403 байта и вернул тот же SHA. Проверить всю последовательность до чтения манифеста, заложить в тест обычный крупный коммит. |
| **P2 · R2-006-F2. Удаление после незавершённой первой настройки оставляет блокировку следующего пакета** | Вывод по коду исправленного Setup. Если регистрация приложения уже зафиксирована, а завершение начальной настройки вернуло ошибку, остаётся `RDCRelayFirstInstall.pending`. Его удаляет успешный `FinishFreshIntent`. Путь `--uninstall` допускает удаление зарегистрированного пакета, но после фиксации удаления не обрабатывает его pending-файл. Следующая установка с другим манифестом получает `V16_FRESH_INTENT_COLLISION`. Отказ при смене манифеста подтверждён тестом. Полную последовательность «ошибка настройки → удалить → поставить другой пакет» в гостевой ОС в этом ревью не исполняли. | После подтверждённого удаления согласовать состояние pending с журналом и SHA именно удаляемого релиза, сохранить чужой файл при несовпадении. Проверить штатное удаление из этого состояния и установку следующего пакета. Обесточивание для этого сценария не требуется. |

**Что прошло.** Ревьюер независимо запустил шесть наборов в Windows PowerShell 5.1. Все 183 проверки прошли: метаданные 28, состав и валидация пакета 92, иконки 10, загрузчик обновлений 20, автозапуск 14, четыре прошлых замечания 19. Дополнительно повторён собственный тест из предыдущего ревью. Оба метода точного Setup приняли системный ярлык на OneDrive Desktop. Правильные служебный EXE и диспетчер без своих контрольных файлов восстановились. Чужие файлы и посторонний junction по-прежнему отклоняются в целевых тестах. Ограничение HTTP сработало для объявленной и порционной передачи сверх лимита и для перенаправления. Таким образом, исходные **F1/F2 закрыты в проверенных сценариях**, восстановление F3 для повторного запуска того же Setup и защита размера F4 подтверждены. Отдельные регрессии описаны выше.

Portable SHA-256 — `919AA36AA402E1026CEBAFC6040EFA738CD2F309406638FED0F24DB848F380BF`. Все 30 записей Portable совпали со staging. Все 35 файлов FullHost локального Git-дерева `d4f1ec34d3cce5cba49bde2fe9fdef51d7639ea1` (68 файлов) совпали с соответствующими входами сборки, исходниками и манифестом. Рабочая копия продукта чистая. На момент сверки публичный preflight указывает на прежний `a6580eb`, main и stable — на `5b1fdf5`, тег v1.6.0 отсутствует. Статус подписи Setup — NotSigned.

**Что подтверждается архивом программиста.** В четырёх результатах Sandbox для исправленного Setup указаны exit 0 при восстановлении maintenance, завершении первой установки с незавершённым диспетчером, обычном удалении и повторной установке. В первом случае сохранился выключенный автозапуск, во втором включился ожидаемый автозапуск и очистился pending, после удаления отсутствовали регистрация, ярлыки и Run, после переустановки совпали 29 хешей. Эти архивные наблюдения отделены от собственных прогонов ревьюера. Тест удаления проводился после завершения начальной настройки.

По решению владельца реальная перезагрузка и дальнейшие жёсткие прерывания отложены. Полный цикл на облачном Desktop, обновление через реальную кнопку и опубликованный HTTP-канал, обслуживание в двух сессиях, чистая установка и миграция с 1.5.18 именно этим бинарником остаются за пределами полученного подтверждения.
