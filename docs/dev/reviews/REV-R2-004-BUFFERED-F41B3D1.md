## Пять критериев

| Критерий | Независимое подтверждение |
| --- | --- |
| 1. Offset, границы строк и буфер согласованы после ошибки callback | После чтения всего блока и ошибки сохраняются очередь полных строк, JSON Fragment и незавершённые UTF-8 байты. Проверены ошибки callback вместе с FileShare.None, разрывы 1+3, 2+2 и 3+1 четырёхбайтового маркера, граница чтения 32768 байт. |
| 2. Прочитанные, но ещё не обработанные полные сообщения сохраняются | Собственный тест вызывает ошибку **после** записи побочного эффекта callback. Последующие tool start/completed/Ready доходят в исходном порядке; уже вызванная строка не повторяется. При трёх последовательных ошибках и дописывании новых событий старая очередь обрабатывается до новых байтов, без потерь последующих строк и дублей. |
| 3. Первый следующий корректный Ready принимается | Единственный блок `Channel closed\nDesktop Commander Remote is connected\n`: первый callback падает, следующий poll на EOF принимает уже прочитанный Ready. Второй Ready не записывается. То же подтверждено после повторных sharing failures и после failed tool callback. |
| 4. Нет ложного Ready от JSON; прежние R2 fixes сохранены | Собственный исходный partial JSON → lock → suffix остаётся Fault с нулём connection markers; реальная отдельная следующая строка Ready принимается. Too-long physical line подавляется до LF, UTF-8 не теряется. После пустого lock/unlock остаётся Fault. Tool completed после Channel closed не подтверждает транспорт. Усечение журнала удаляет старый queued Ready, первый новый Ready принимается. |
| 5. Полная регрессия и точный пакет | Полный текущий WinPS runner 72/72; целевые тесты запущены на реальном packaged observer/DLL. Проверены встроенный Setup, manifest и безопасная активация Portable. Состав старых тестов не сокращён. |

Механизм соответствует заявленному контракту: `PendingLines` и индекс фиксируются до callbacks; индекс продвигается перед вызовом. Поэтому сама строка, обработчик которой упал, может остаться с неопределённым результатом и не повторяется, а следующие полные строки остаются в очереди. Проверки включают callback, уже успевший выполнить побочный эффект. Неуспешное декодирование **до фиксации** очереди по-прежнему подавляет недостоверный остаток до LF. Ошибка открытия файла сохраняет ранее согласованный cursor и буферы. Reset при усечении/замене launcher также очищает очередь; усечение проверено динамически, ветка смены launcher просмотрена по коду.
